## Why

SDR's root READMEs contain a rigorous public contract, but they front-load reference detail before showing the outcome of a completed investigation. Beginners need a distinctive, goal-oriented entry point built around SDR's own evidence chain, plus a short bilingual path through the smallest supported lifecycle without overstating release or agent status.

## What Changes

- Reorganize both root READMEs around `question -> evidence -> optional probe -> human-approved decision -> reusable asset`, with verifiable badges, an explicit alpha/source-only notice, source installation, a five-minute synthetic tour, mode selection, confidence boundaries, integrations, and task-oriented documentation links.
- Add paired English and Spanish documentation homes that route readers by goal rather than file name.
- Add paired English and Spanish beginner guides using only the maintained synthetic light-mode fixture and deterministic offline commands.
- Extend documentation validation to protect bilingual concepts, internal links, fixture references, current source-only acquisition, Git side effects, evidence boundaries, and the three `documented` agent integrations.
- Update GitHub repository description and topics to express SDR's own product identity without claiming a release or package-index publication.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `public-documentation`: Add progressive, bilingual onboarding, documentation navigation, and a validated synthetic beginner lifecycle while preserving honest acquisition, evidence, Git, integration, and release claims.

## Impact

This change affects `README.md`, `README.es.md`, new documentation entry points and beginner guides, documentation parity/link validation, public documentation tests, maintenance guidance, changelog, and GitHub About metadata. It does not change CLI, lifecycle, schemas, integrations, package installation behavior, or release availability.
